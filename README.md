# Telegram-бот университетского расписания

Production-ready бот на aiogram 3 получает недельные XLSX из публичной папки Яндекс Диска, показывает расписание выбранной группы и сообщает только затронутым пользователям о конкретных изменениях. Источник изолирован от Excel-парсера, domain diff — от Telegram, а SQL — от обработчиков.

## Архитектура

- `app/sources` — официальный API публичных ресурсов Яндекс Диска, timeout, retry и выбор актуальной версии.
- `app/schedule` — immutable domain-модели, XLSX-парсер, matching/diff, запросы расписания и persistence версий.
- `app/users` и `app/storage` — async SQLAlchemy repository поверх SQLite; бизнес-код не зависит от выбранной СУБД.
- `app/background` — сериализованная фоновая проверка, SHA-256 и идемпотентная фиксация версии.
- `app/notifications` — фильтрация подписчиков по группе и безопасное разбиение сообщений.
- `app/bot` — команды, registration/settings flow, клавиатуры и форматирование.

Загрузчик одновременно хранит актуальную и ближайшую следующую неделю, если второй файл уже
опубликован. Кнопка «Неделя» показывает выбор диапазона дат. После начала новой недели она
автоматически становится текущей, а прошлая исчезает из выбора без ложной рассылки об удалении
всех старых пар.

Парсер находит листы вида `N курс` и группы непосредственно в строке заголовков. Для любой координаты он проверяет merged range и читает верхнюю левую ячейку, поэтому общее занятие корректно назначается каждой охваченной группе. Дата переносится на последующие строки дня, а номер и время пары читаются из столбца B.

Источник принимает только имена недельного расписания, извлекает номер недели, начало и дату после `с изм.`, причём поддерживает кириллическую `с` и латинскую `c`. Выбирается последняя версия недели, содержащей локальную дату Перми; иначе ближайшая будущая или последняя прошедшая. Имя не является идентификатором: после скачивания вычисляется SHA-256.

Diff сначала исключает точные совпадения, затем минимально сопоставляет занятия одной группы и даты по предмету и изменяемым полям. Это отличает перенос/смену аудитории от удаления с добавлением. Первая версия становится baseline без рассылки; hash с уникальным индексом не обрабатывается дважды. Новый пользователь не получает историю, потому что рассылка выполняется только во время будущей обработки версии.

## Настройка и запуск

Создайте бота через `@BotFather`, скопируйте `.env.example` в `.env` и укажите токен:

```env
BOT_TOKEN=123456:secret
YANDEX_PUBLIC_URL=https://disk.360.yandex.ru/d/At7POE_VL0oNiA
TIMEZONE=Asia/Yekaterinburg
CHECK_INTERVAL_SECONDS=300
DATABASE_URL=sqlite+aiosqlite:///./data/bot.db
CALENDAR_HOST=0.0.0.0
CALENDAR_PORT=8080
CALENDAR_BASE_URL=https://bot.example.com
```

`CHECK_INTERVAL_SECONDS` должен быть не меньше 30. Для PostgreSQL достаточно заменить SQLAlchemy URL и установить async-драйвер — repositories и бизнес-логика остаются прежними.

`CALENDAR_BASE_URL` — публичный HTTPS-адрес сервера без завершающего `/`. Endpoint
`/calendar/<личный-token>.ics` отдаёт всегда актуальное расписание, а `/health` используется
для health check. Пробросьте порт `8080` через reverse proxy (Caddy/Nginx/Cloudflare Tunnel).
Без публичного адреса кнопка календаря всё равно отправляет `.ics` для разового импорта, но
автоматическая синхронизация календарного приложения работать не сможет.

Запуск локально:

```bash
uv sync --python 3.13
uv run python -m app.main
```

Docker с постоянным томом данных:

```bash
docker build -t schedule-bot .
docker run --env-file .env -v schedule-data:/app/data schedule-bot
```

Приложение использует long polling. При остановке отменяется scheduler, закрываются Telegram session и SQLAlchemy engine.

## Подписка на календарь и Railway

Кнопка `Календарь` в профиле выдаёт персональную HTTPS-ссылку вида
`/calendar/<token>.ics`. Это динамическая подписка: сервер собирает ICS при каждом запросе
из текущего расписания пользователя и учитывает его скрытые предметы. Скачивание `.ics` —
отдельный разовый снимок, который сам не обновляется. Сменить token можно из меню календаря;
старый адрес после этого сразу возвращает `404`.

У событий стабильный `UID`: перенос времени, смена аудитории или преподавателя обновляет
существующее событие, а удалённая из актуального расписания пара исчезает из следующего
снимка feed. Частоту загрузки подписки определяет Google Calendar или Apple Calendar, поэтому
изменение на сервере может отобразиться не мгновенно. Endpoint поддерживает `ETag`/`304`, но
не разрешает длительное кеширование.

Для Railway добавьте Variables:

```env
BOT_TOKEN=<новый token от BotFather>
CALENDAR_BASE_URL=https://<домен Railway>
DATABASE_URL=sqlite+aiosqlite:////app/data/bot.db
```

Railway сам передаёт `PORT`; приложение слушает его с приоритетом над `CALENDAR_PORT`.
Подключите Volume с mount path `/app/data`, иначе пользователи и персональные ссылки потеряются
при redeploy. В Public Networking создайте HTTPS-домен и используйте его целиком в
`CALENDAR_BASE_URL` без пути. Healthcheck path: `/health`.

Чтобы добавить подписку в Google Calendar, откройте веб-версию: «Другие календари» → `+` →
«Добавить по URL». На iPhone/iPad: «Календарь» → «Календари» → «Добавить календарь» →
«Добавить календарь подписки». На macOS: «Календарь» → «Файл» → «Новая подписка на календарь».

## Проверки

Обычный suite полностью offline; реальный XLSX сохранён как fixture. Он проверяет все 10 ожидаемых занятий `РИС-23-3`, но эта группа нигде не используется production-кодом.

```bash
uv run ruff format --check .
uv run ruff check .
uv run mypy app
uv run pytest
uv run pytest --cov=app --cov-report=term-missing
```

Для расширения добавляйте новый adapter в нужный внешний слой (источник или Telegram transport), сохраняя domain API. Новые поля занятия добавляются в `Lesson`, сериализацию, distance matcher и formatter; observable поведение фиксируется тестом до подключения handler-а.
